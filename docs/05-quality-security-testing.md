# 质量、安全与测试规范

## 基本质量门槛

- 每次提交的代码必须能够编译。
- 新增业务规则必须有单元测试。
- 修复缺陷时先添加可复现测试，或记录无法自动化的原因和人工步骤。
- 编译警告要调查；不得长期通过关闭警告掩盖问题。
- UI 线程不得执行图片编码、数据库清理等明显耗时操作。

## 仓库级构建规则

- `.editorconfig` 是代码格式和基础代码风格的唯一仓库级来源。
- `Directory.Build.props` 对所有项目统一启用 Nullable、.NET 分析器、确定性构建，并将编译警告视为错误。
- NuGet 使用锁定文件；依赖发生变化时必须审查并提交对应的 `packages.lock.json`。
- 本地完整验证命令：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ./scripts/Verify-Build.ps1
```

- 已经完成依赖还原且只需离线复验时，可添加 `-NoRestore`。
- 验证脚本默认关闭 .NET CLI 遥测。
- 当前目录尚未被 Git 识别为有效仓库，因此暂不创建远程 CI 工作流；启用 Git 后再添加与本地验证命令一致的 CI。

## 隐私和日志

- 不联网、不上传剪贴板内容，不引入遥测。
- 运行日志不得包含完整文字、图片数据、文件完整路径或用户隐私。
- 可记录内容类型、长度、数量、哈希摘要前缀和错误类型。
- 异常信息展示给用户时，不暴露数据库连接信息或系统敏感路径。

## 数据安全

- 删除原始文件是禁止操作。
- 自动清理只能操作 `%LOCALAPPDATA%/ClipHistory/` 下由应用创建的数据。
- 删除图片前验证其规范化绝对路径位于应用图片目录内。
- 数据库写入使用事务；失败时保持原有记录可用。
- 升级数据库前保留可恢复策略，并对迁移进行测试。
- 开机启动的启用和禁用都必须可验证、可逆。

## 自动测试重点

- 文字、图片、文件路径的去重。
- 重复项更新时间和排序。
- 置顶内容永不过期。
- 取消置顶后重置过期起点。
- 1、3、5 天边界时间计算。
- 搜索和类型筛选组合。
- 删除、撤销和清空范围。
- 不存在文件的状态判断。
- 剪贴板自触发循环保护。

## 人工验收重点

- 从记事本、浏览器、截图工具和资源管理器复制内容。
- 多文件、多文件夹和中英文路径。
- 超长文字、透明图片、大图片和快速连续复制。
- 关闭窗口、托盘恢复、彻底退出。
- 快捷键冲突和开机启动开关。
- 中文、英文切换及不同缩放比例。
- 暂停期间不产生新记录，恢复后正常记录。

## 性能目标（首版参考）

- 普通文字复制后，列表在主流电脑上应尽快更新，目标小于 500ms。
- 搜索 5,000 条文字/文件记录时保持可交互。
- 列表使用虚拟化，图片按需加载缩略图。
- 后台无变化时不进行高频剪贴板轮询。
